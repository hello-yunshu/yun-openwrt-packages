# patches/

对**上游包**的补丁，用于在不 fork 上游仓库的前提下修正问题。

## 约定

```
patches/
└── <包名>/
    ├── BASE            # 补丁对应的上游 commit（单行）
    ├── 0001-*.patch
    └── 0002-*.patch
```

- 每个包一个目录，目录名与 `PKG_NAME` 一致
- `BASE` 记录补丁所基于的上游 commit，构建时先 checkout 到该 commit 再打补丁
- 补丁按序号顺序应用，用 `git apply --3way`；**任何一处失败立即停止**，不要跳过或强制合并
- 补丁头部保持在 `git format-patch` 风格，含 `From` / `Subject`，便于追责与上游回馈

## 当前状态

**空目录。** 目前没有需要打补丁的包。

三个自研包直接以自身仓库为源码，不需要补丁；上游依赖（如 `acme-acmesh`）经核对无需修改。

## 什么时候才该放补丁

- 上游包在 25.12 上确实编不过或行为错误，且短期不会修
- 改动很小、能干净地以 patch 表达

如果改动大到需要长期维护，应该向上游提 PR，而不是在这里堆补丁。
